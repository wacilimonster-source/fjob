# 国内基金持仓 · 详细设计

版本 1.0 · 2026-11-09 · 状态：已实施（M7-FUND），本文保留为功能设计与验收依据。

任务编号：M7-FUND；需求编号：ASSET-01-FUND；计算编号：CALC-FUND、CALC-TOTAL-FUND。

本文将用户对“资产风浪增加国内基金，按股票相同方式添加，保持简单”的要求细化为可开发、可测试的规格。设计中的行为已在本轮 M7-FUND 落地；实际命令结果、在线来源抽样与未验证项见 [验收与验证记录](06-acceptance.md)。用户后续明确提出的新要求优先。

实施交接及可复制任务见 [11-handoff-domestic-fund-implementation.md](11-handoff-domestic-fund-implementation.md)。

## 1. 范围与产品决策

### 1.1 本期要做

1. 在“资产风浪”增加基金持仓，复用股票持仓的添加、编辑、删除、列表和刷新体验。
2. 支持境内募集、以人民币计价、按**单位净值**估值的普通场外开放式基金，包括常见股票型、混合型、债券型、指数型及 ETF 联接基金。境内募集的人民币 QDII 份额，若来源能确认单位、币种及数据口径，也可按本设计录入；不能按境内股票日历推断其净值日期。
3. 输入六位基金代码，尝试自动查名称；输入持有份额、每份成本。名称允许修改，断网时允许先保存，待联网确认。
4. 使用已公布单位净值，展示净值日期、持有盈亏和今日浮动。基金今日浮动进入首页、小部件总额。
5. 在首次引导的资产步骤提供同样的入口；重走引导时保留已有基金、精度和身份。
6. 只支持 Android；按现有项目要求本地构建 debug APK，不自动发布或部署。

### 1.2 本期不做

- 货币基金、场内 ETF/场内持有份额、境外注册基金、外币计价份额。货币基金的万份收益不是单位净值；场内持有应以交易价格估值。ETF **联接基金**如满足 1.1 条件，属于支持范围。
- 基金交易、买卖流水、自动同步券商账户、自动手续费、分红再投资、盘中估值与收益预测。
- 新增后端用户账户、将个人财务信息传给行情服务、iOS。

场内外可使用同一基金代码的产品，以用户在本功能录入的**场外持有**为前提；不得把场内持仓的市价误标为本功能的单位净值。若来源无法可靠区分品种、币种或持有口径，该标的保存为待确认，不参与净值计算。已确认不支持的品种应明确提示，不按普通基金继续计算。

## 3. 交互设计 ASSET-01-FUND

### FND-UI-01 添加与编辑

“资产风浪”中原“添加持仓”位置改为两个并列按钮：`添加股票`、`添加基金`。股票使用现有表单及规则；基金使用相同样式的底部表单：

```text
添加基金持仓

基金代码             [ 000001                 ]
                     已识别：华夏成长混合
基金名称（可修改）   [ 华夏成长混合           ]
持有份额 / 份        [ 1000.2500 ]
单位成本 / 元每份    [ 1.2000    ]

                     [ 保存持仓 ]
```

- 六位数字以字符串保存，保留前导零；输入六位后防抖查询。名称可由用户编辑，晚到的查询结果不能覆盖用户手动输入，也不能把旧代码的结果应用到新代码。
- 基金份额和单位成本都必填、非负，最多四位小数；份额允许 0。单位成本上限沿用当前成本上限 `100000`，份额上限为 `10000000`。不可用浮点计算或静默截断超出的小数。
- 同一个基金代码只保留一笔当前持仓；不同基金 A/C 份额代码分别保存。`FUND.CN.000001` 与股票 `CN.SZ.000001` 互不冲突。
- 查询失败、无网络或无法确认品种时，允许保存并显示“待联网确认”；只保存代码、名称、份额和成本，不生成模拟净值。
- 来源已明确表明是货币基金、场内 ETF 或外币份额时，阻止按普通基金保存，显示对应原因。离线保存后若联网发现不支持，保留用户输入并显示“不支持该基金类型”，不计算、不悄悄删除。
- 编辑支持修改名称、份额、成本及代码；变更代码前检查重复。涉及旧 ID 关闭和新 ID 新增时，必须在单个事务中完成，失败保留原持仓。保存后按当前份额重估，不虚构交易。
- 删除沿用当前二次确认和版本化保存；示例模式仍不得写入正式账本。

### FND-UI-02 资产卡片

```text
基金 · 华夏成长混合  000001                 [编辑] [删除]
1000.25 份 · 单位成本 ¥1.2000 / 份

最新单位净值       今日浮动          持有盈亏
¥1.2356 / 份       +¥10.00          +¥35.61
净值日期 2026-11-09 · 东方财富 · 日终数据
按当前份额估算，不包含已发现金分红及未反映在成本中的费用。
```

数字为固定示例，不是默认值或实时行情。净值显示至少四位小数；来源有更多有效位时保留，不得先压到股票的两/三位精度。金额显示两位小数。无净值、基准、验证或有效日历时使用明确的“待更新/待确认”，不得用 `0.00` 替代未知。

日终数据只保证**净值日期**，不保证披露时刻。无真实发布时间时界面只标净值日期；如展示抓取时刻，必须标为“获取时间”，不能标为“净值发布时间/实时价”。缓存故障时保留最近有效净值和真实日期，并标明缓存或待更新。

### FND-UI-03 引导、首页与桌面

- 首次引导资产步骤提供相同的股票/基金入口及卡片；核对页分别显示股票、基金数量和黄金摘要。不添加资产仍可继续。
- 重走引导保留已保存的基金、名称、份额和成本；取消重走不得改账本。旧草稿缺少资产类型时按股票兼容。
- 首页在 A 股与黄金附近增加 `基金 · 今日浮动`，状态说明标注净值日期或待更新；解释区加入基金净值口径。仅无基金时基金项是已知 0。
- 小部件总额计入基金。中/大号原股票分项改为 `股票+基金`；黄金保留独立分项。这个合计由 Dart 计算，任一组成未知时该分项显示待更新，主总额显示已知小计并标不完整。无基金时该分项数值与原股票分项相同。小号显示更新后的总额和状态。
- 小部件时间标注区分“计算截至”和净值日期；不得将抓取时间冒充净值发布时间。隐私打开时所有金额、无障碍文案和预览继续隐藏。
- 继续使用现有纸感、粗线条、固定浅色；检查 320dp、系统大字体及键盘弹出时表单可滚动。

## 4. 净值和计算契约

### 4.1 标识、数值与输入

新增内部标识 `FUND.CN.<六位代码>`，例如 `FUND.CN.000001`。持仓的 `quantity` 为基金份额，`costPerUnit` 为人民币/份；两者以规范十进制字符串存储和传递。`finance_core` 增加 `InstrumentKind.fund`，未知 ID 不能默认当作基金；原 A 股/黄金身份和计算保持不变。

基金净值使用来源公布的**单位净值**，不得使用累计净值、盘中估算值、万份收益、场内市价或用户成本代替。解析和计算沿用 `Rational` 等精确十进制语义；来源的更多有效位保留，合计前不四舍五入，展示金额按项目 `HALF_UP` 保留两位。`null` 表示未知，真实 0 与未知不同；来源缺失符号、非法数字或无日期时不得转换成 0。

净值应为非负且有来源确认；只有来源明确发布有效零净值时才能接受 `0`，空值、缺失标记和解析失败均为未知。上一有效净值及日期必须成对存在，日期早于当前净值日；同一来源不能仅以不同抓取时间伪造两条不同日期的净值。

### 4.2 净值记录

基金采用独立的 `FundNavSnapshot`/等价类型，不要求旧股票/黄金 `Quote` 填造一个不存在的时间。字段名以实际契约为准，必须保留以下语义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `instrumentId` | string | `FUND.CN.000001` 格式 |
| `navCny`、`navDate` | 十进制字符串/null、日期/null | 最新有效单位净值和所属净值日 |
| `previousNavCny`、`previousNavDate` | 同上 | 同一来源、同一标的的前一有效单位净值及日期；不可将不同来源拼接 |
| `actionStatus` | `none` / `detected` / `unknown` | 前一净值日之后至本净值日之间的分红/拆分状态 |
| `fundCalendar` | `mainland` / `unknown` | 来源已确认适用境内基金日历，或不确定；QDII 默认 unknown，除非有可靠的专用日历 |
| `eligibility` | `supported` / `unsupported` / `unknown` | 品种、持有口径、人民币计价是否确认可用 |
| `fetchedAt` | RFC3339 UTC | 真正抓取时间 |
| `publishedAt` | RFC3339 UTC/null | 来源提供的真实发布时间；来源没有时为 null |
| `source`、`sourceRevision` | string、非负整数/null | 来源和其可确认的修订版本；不可用哈希大小冒充修订顺序 |
| `quality`、`sourceLicenseStatus` | 项目已有枚举 | 已公布净值为 `eod`；许可按实际证据记录，未知或仅开发验证不得标 verified |

日期为 `YYYY-MM-DD`，业务日期按 `Asia/Shanghai`。`navDate` 不是 `publishedAt` 或 `fetchedAt`。接口没有披露时间时不得用当天 15:00、午夜或抓取时刻填充 `publishedAt`。对旧的 `quotesAsOf`，若参与汇总的基金只有日期、没有可信精确报价时刻，则该汇总精确时刻为 null；基金卡片仍显示各自净值日期。

来源有明确、完整的分红/拆分覆盖证据，且该区间没有事件时才能设 `actionStatus=none`；确认有事件为 `detected`；缺字段、覆盖范围不明、获取失败或解析不清为 `unknown`。不能把来源空响应、失败或尚未验证字段语义直接当作“无事件”。

以下为计划中的网关响应示意，数字均为固定测试值。`publishedAt`、`sourceRevision` 必须允许 null；实际源码与 OpenAPI 必须对齐：

```json
{
  "requestId": "fund-example",
  "serverTime": "2026-11-09T12:30:01Z",
  "refreshAfterSeconds": 1800,
  "items": [
    {
      "kind": "fundNav",
      "instrumentId": "FUND.CN.000001",
      "navCny": "1.2356",
      "navDate": "2026-11-09",
      "previousNavCny": "1.2256",
      "previousNavDate": "2026-11-06",
      "actionStatus": "none",
      "fundCalendar": "mainland",
      "eligibility": "supported",
      "fetchedAt": "2026-11-09T12:30:00Z",
      "publishedAt": null,
      "source": "fixture",
      "sourceRevision": null,
      "quality": "fixture",
      "sourceLicenseStatus": "developmentOnly"
    }
  ]
}
```

同一净值的值与日期应成对出现；缺失有效净值时使用 null 或分项错误，不能只有值而没有所属日期。真实已公布净值的质量为 `eod`；示例中 `fixture` 仅用于测试。`fundCalendar=mainland` 意味着来源或可靠资料已确认该产品适用对应日历，并不代表当前日历一定覆盖统计日；现有本地 2026 年日历不能外推到覆盖范围之外。

### 4.3 持有盈亏 CALC-FUND-HELD

```text
持有盈亏 = (navCny − costPerUnit) × quantity
```

- `quantity=0` 是已知 0，即使没有净值；其他情况下，只有基金资格已确认支持、净值与净值日期有效且不晚于统计日时才可算。
- 该值仅为按当前录入份额和成本估算的未实现盈亏，不包含已发现金分红、已实现盈亏，也不自动处理未被用户成本反映的费用。
- 若净值区间有分红/拆分，提示用户核对并更新份额/成本；持有估值仍须明确“按当前录入估算”。未知资格、无净值或未来日期不得参与持有估值。

### 4.4 今日浮动 CALC-FUND-DAILY

按以下顺序对**每只基金**求值，不能复用股票的“交易日当前价/昨收”或黄金夜盘分支：

1. 份额为 0：今日浮动为已知 0。
2. 资格不是 `supported`、没有有效最新净值/净值日，或净值日在统计日之后：未知，显示对应待确认/待更新。
3. `navDate == 统计日`：只有同来源上一有效净值及其更早日期有效，且 `actionStatus=none`，才计算 `(navCny − previousNavCny) × quantity`。基准缺失、非同源、日期顺序错误或事件状态未知/已发生时，今日浮动未知并显示待更新/待核实。
4. `navDate < 统计日`：若该基金已确认适用境内基金日历，且该统计日被覆盖的有效日历明确标为休市，今日浮动为已知 0；其他情况均为未知。QDII、没有日期覆盖、未知品种或不可靠日历不得依据星期几猜休市。最新净值仍可用于持有估值，并显示真实净值日期。
5. 不能把上一个净值日的涨跌额当作今天的涨跌，也不能将未来的日终净值填入预先生成的小部件时间线。

基金的净值日、上一净值日和事件判断必须属于同一来源的可比数据。来源切换时清除旧的不兼容基准；缺失任一条件即只展示可计算部分。分红/拆分事件当天不自动推算现金分红或再投份额。

### 4.5 首页和部分可计算合计 CALC-TOTAL-FUND

```text
已知小计 = 工资 + Σ已知股票今日浮动 + Σ已知黄金今日浮动
                 + Σ已知基金今日浮动 − 已知住房分摊 − 已知车贷分摊
```

- 工资不可算时仍沿用 `unavailable`。其他应参与项有未知时为 `partial`，显示已知小计及缺失项；所有应参与项已知时为 `complete`。
- 多只基金不能因一只待更新而丢弃其他已知基金的数值。计算层需同时提供基金已知小计和完整性；分项总值未知时不要把已知小计标成完整基金总收益。
- `stockDaily`、`goldDaily` 保留原有类型语义，基金不得偷偷累加进股票字段。先按完整精度求和，再显示到分；一分误差解释沿用现有契约。
- 为小部件提供单独的 `stockFundDaily`：只有股票、基金两类今日数均完整时，才等于二者完整精度之和并最终舍入；否则为 null。不得在 Kotlin 重新相加。

## 5. 来源、刷新与失败

### 5.1 来源候选及证据

当前开发客户端已使用东方财富公开接口。可把天天基金/东方财富作为**开发验证候选**：[开放式基金净值页](https://fund.eastmoney.com/fund.html)说明当日净值通常在交易日 16:00—23:00 更新；[AKShare 源码](https://github.com/akfamily/akshare/blob/main/akshare/fund/fund_em.py)记录了基金目录、历史单位净值及分红/拆分的候选入口。

2026-11-09 本地仅做过只读抽样：基金代码 `000001`、`110022` 的历史净值候选接口返回 HTTP 200，`000001` 的名称候选接口返回“华夏成长混合”。同日基金目录候选返回了 `000001`、货币基金 `000198`、ETF 联接 `000051`、场内 ETF `510300` 等记录。**这不证明接口稳定、字段覆盖完整、所有基金均可识别，也不证明公开展示许可。**

目录抽样中 `000051` 与 `510300` 的基金类型均为“指数型-股票”，而 `000055` 名称标识美元份额；因此仅凭目录类型、代码首位、是否包含“ETF”、或默认 CNY 都不足以可靠区分本期范围。实施时需验证可用的品种、份额币种和持有口径信息；不能确认时按 unknown，不能将待确认伪装为支持。

候选接口可按少量公开样本进行低频验证：

- 目录：`https://fund.eastmoney.com/js/fundcode_search.js`；返回全量目录，只能按可接受频率缓存，不能每 250ms 或每个输入字符下载。
- 净值：`https://api.fund.eastmoney.com/f10/lsjz?fundCode=000001&pageIndex=1&pageSize=2`，候选返回 `FSRQ`（日期）、`DWJZ`（单位净值）等；实际字段、历史顺序、分红和拆分覆盖须验证。
- 名称/其他历史资料：`https://fund.eastmoney.com/pingzhongdata/000001.js`；这是上游 JavaScript 数据文件，应以受限解析读取所需数据，**不得执行远程脚本**。不要因文件中的估值字段而使用盘中估值。

开发时至少用普通基金、ETF 联接、货币基金、场内 ETF、外币份额和已知分红/拆分样例核实分类及事件字段；若字段不足，以待确认/待核实完成降级，记录限制，不得伪造基准或将所有来源自动标记为无事件。已发布净值可用于持有估值，但无法确认事件时今日收益保持未知。

### 5.2 接入与刷新

- 默认客户端直连开发候选和 `FJOB_MARKET_GATEWAY` 网关模式都要支持本设计。基金 ID 与股票/黄金分组请求并合并结果；一个基金的失败、解析错误或限流不能覆盖其他基金或股票的成功结果。
- 基金在 App 启动、回到前台、添加/编辑后按需刷新；普通自动刷新使用缓存，建议同标的至少 30 分钟间隔。用户手动刷新可主动重试，但需防重复点击、遵守服务端 429/`Retry-After` 和来源限制；不新增 15 秒轮询或后台常驻。
- 离线或请求失败保留最近有效缓存；新标的无缓存则待更新。失败不得更改原净值日或原抓取时间。
- 按标的和净值日期防乱序：较旧净值日不能覆盖较新值；同日优先采用来源可证明的更高修订。没有上游修订时，用请求发起代次保证晚到的旧请求不能覆盖新请求；必要时记录来源重新抓取时间，并对同日修订显式测试。切源时不可拼接两源净值与基准。
- 只发送基金代码/标的 ID 和公共查询参数，不发送份额、成本、工资、租金或贷款。日志、异常和分析不得包含个人持仓数据。
- 开发验证源须标 `developmentOnly`/`unknown`；对外生产启用以来源访问和展示许可的书面记录为门禁。签名或发布不是本任务的自动步骤。若没有具备许可的生产源，release 应保持基金公开源停用并显示来源不可用；不得用 fixture 冒充真实净值。

## 6. 工程设计

### 6.1 数据与迁移

1. 持仓表沿用 `holding_versions` 的十进制文本、版本和账本修订；名称沿用 `instrument_directory`，增加基金市场映射。按完整 instrument ID 判重，不通过六位代码判重。
2. 当前 SQLite v3 升为 v4，新增独立的 `fund_nav_cache`（或语义等价的新表），保存 4.2 所需净值、日期、基准、事件、资格、来源、许可和抓取信息。允许无净值或无发布时间；不要将基金伪装成旧 `quote_cache` 的非空 `quote_at`。
3. `onCreate` 必须生成最新结构，`onUpgrade` 支持已有低版本按顺序升级至 v4。旧股票、黄金、工资、费用、草稿、名称、账本修订、quote 缓存、小部件队列不能被截断或改义。迁移事务失败时回滚；有旧 v1/v2/v3 样本则都测到 v4。
4. 扩展 `HoldingDraft` 的资产类型及序列化，旧草稿缺字段默认股票。`SetupDraft.fromLedger`、引导校验、提交和回显按类型分别处理 0/4 位份额及成本精度；保留原始非法输入的草稿恢复行为。
5. 更新 `pending_quote`/等价状态：当前 `upsertHolding` 固定写 0，基金未确认时需正确持久化待确认。确认与刷新只更新公共资料/状态，不丢弃用户手动名称、份额和成本。

### 6.2 行情契约及网关

在 `contracts/market-gateway.openapi.yaml` 保持旧股票/黄金的请求响应兼容，并为基金增加明确契约：

- `/v1/instruments/search` 可选 `kind=stock|fund`，省略时保留原行为；基金结果的市场为 `CN_FUND`、单位为 `fundShare`，提供 `eligibility` 及不支持原因。代码和名称均为字符串，保留前导零。已确认不支持与未确认是不同状态。
- `/v1/quotes/batch` 继续只接收最多 30 个唯一标的 ID；基金结果新增 `kind=fundNav` 的独立响应分支，包含 4.2 字段，并与原证券 Quote、分项错误形成明确可区分的 `oneOf`。基金日期型净值不填造原股票 `quoteAt`。所有请求 ID 均恰好返回一项，部分失败可共存。
- 增加确定性 fixture 基金目录/净值及单项错误，并更新 FastAPI/Pydantic 模型、直连客户端、网关客户端与测试。fixture 仅示例/测试使用。公共候选可以独立实现成可替换适配器，不能要求个人用户填写行情密钥。

基金数据表和 API JSON 中价格、份额及金额均用十进制字符串；不能使用二进制浮点作为最终业务数。网关和日志不得接收或记录份额及成本。

### 6.3 Android 小部件快照 v2

保留现有 `contracts/widget-snapshot.schema.json` 的 v1 含义和 fixture；新增 v2 schema，按 `schemaVersion` 验证。v2 在现有 `amounts` 基础上新增必填可空金额 `stockFundDaily`，保留 `stockDaily` 和 `goldDaily` 原义。隐私或 tombstone 时该新金额也必须为 null。

- Dart 生成 v2 正常/隐私/tombstone 时间线；`timelineVersion` 可继续为 1。原生 Kotlin 接受合法 v1 和 v2、拒绝未知版本及未知金额键；v1 的股票展示沿用 `stockDaily`，v2 显示预计算 `stockFundDaily` 并标“股票+基金”。
- 旧 v1 快照在升级后可读。已保存 v2 后，同账本修订的晚到 v1 不得覆盖 v2；更低账本修订仍拒绝。tombstone 与隐私保护继续生效，旧队列重试不得恢复已清空或已隐藏的金额。
- 小部件只展示 Dart 生成的金额与状态，不在 Kotlin 中重新计算；`quotesAsOf` 缺精确来源时刻时为 null，不改变 `computedAt` 的计算时间含义。未来时间线固定现有净值，只根据真实日期和已知日历判断，不能预测未来净值。
- 同步 v2 JSON Schema、Python schema 校验、Dart 快照测试、Kotlin 解析和乱序/隐私测试；只涉及 Android，不新增 Swift 实现。

例如 FND-15 的 v2 `amounts` 可为以下结构；此时快照 `completeness` 为 `partial`，因为有一只基金尚未更新：

```json
{
  "total": "82.00",
  "wage": "100.00",
  "stockDaily": "-20.00",
  "goldDaily": "5.00",
  "stockFundDaily": null,
  "housing": "10.00",
  "car": "3.00",
  "principal": null,
  "interest": null,
  "rent": "0.00"
}
```

此处 `total` 含已知基金小计，`stockFundDaily` 因另一只基金未知而为 null。隐私打开时上述**所有**金额字段均为 null。
