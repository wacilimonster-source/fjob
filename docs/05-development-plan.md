## 2. 每个任务的输入与输出

### M0 建项

输入为本交付文档、Windows 本地环境和可用 GitHub 仓库。创建 apps/mobile 与 packages/finance_core，登记包标识的占位值。选择一套确实能构建的 stable 工具链，提交版本锁和命令说明。

输出包括 Android debug 编译、macOS CI iOS simulator 编译日志。CI job 独立报告 Flutter 主应用与 Widget extension 状态。测试密钥和生产签名尚缺时记录任务依赖，不提交伪造签名文件。

### M1 领域

输入 `04-data-and-calculation-contracts.md` 与 fixtures。先实现值对象和纯函数，再实现排班展开、区间交集、月内版本分段和完整性汇总。

除普通 fixture 外增加特定回归测试，包括重叠排班、跨月夜班、闰年2月、休市、黄金夜盘、缺本金、缺行情、换住房方案和零工资零排班。每个测试明确输入时区、基准和预期。

### M2 引导和存储

输入产品 ONB-01 至 ONB-07。实现实体表、草稿和版本迁移，保存时事务化。新用户表单初始为空，例子只在 placeholder 或隔离示例中出现。

覆盖半途关闭、重复确认、磁盘写入失败、旧数据迁移和重走取消。输出流程录屏或截图及测试结果。

### M3 页面与动效

先迁移布局和纯展示，接入已有领域输出。小人、房和车采用共享绘制组件，不重新发明写实素材。按状态表实现敲键盘、硬币路径、天气和安慰。

场景层只接收状态和归一化参数，不直接访问数据库或报价 HTTP。减少动效和大字号作为该任务完成条件；界面固定浅色。

### M4 平台扩展

先用 JSON Schema 及固定 fixture 建立原生消费测试，再接桥接。Android 验证 RemoteViews 配置变化、进程死亡及 WorkManager 延迟。iOS 验证 Widget target、App Group、timeline、隐私和安装后的占位界面。

快照来自 Dart 单一计算源。原生使用预计算结果，避免 Kotlin、Swift 自行分摊后与 App 出现差异。

### M5 行情验证

先实现固定契约与 fake provider。公开候选为 AKShare 项目已记录的A股和上金所参考数据。写一次性验证工具读取少量标的，记录调用时间、原始字段、单位、交易日、缓存和故障行为，确认其可满足适配能力。

记录是否免 key、实际访问限制、数据延时、公开展示许可证据、授权联系和失败应对。取得许可或选择可用于目标场景的替代源后再启用生产配置。不能以服务端缓存来替代来源许可结论。

### M6 发版

生成受保护的 Android/iOS release 工作流。按架构逐项落实证书、profile、App Group 和上传凭据。发布任务先验证版本号、签名完整性和产物校验和，再上传。

记录 iPhone TestFlight 安装与小部件验收，iOS 编译通过和实际运行通过分别填写。最后移交使用说明、配置清单与回滚步骤。

## 5. 交接报告模板

每次任务报告包含任务编号、需求编号、输入契约版本、实现摘要、关键文件、执行过的命令与结果、截图/产物路径、偏差、迁移和回滚方法、下一任务可用接口。

合并前检查文档中的同名字段、OpenAPI、JSON Schema、测试 fixture 与实现一致。调整业务口径时先修订契约及预期，再修改计算和 UI，保证后续模型可以追踪决策。
