# 首页双核心指标 · 产品原型与开发交接

版本 1.1 · 2026-11-09 · **设计交付；M8-HOME 已于 2026-11-09 实施**。任务编号 **M8-HOME**，细化 HOME-01、H01、H02、H03；以本文件和原型为首页布局的新依据，金额和排班计算仍以 `docs/04-data-and-calculation-contracts.md` 为准。1.1 按用户要求增加两项指标的显示配置，并细化卡片边框和衔接。当前 M7-FUND 的指定任务与本任务彼此独立；基金若已合入，首页必须兼容其完整性和今日浮动，见 `docs/10-design-domestic-fund-holdings.md`。

## 1. 目标、范围与现状

用户打开首页时应先读到自己选择关注的答案：**多久下班**、**今天的生存结余是多少**。默认同时显示，两项都应在首屏可见；用户也可选择仅显示其中一项。双卡时下班倒计时位于金额上方。下班时间、计薪进度及数据是否完整，要能和各自数字一起被理解。

当前 `apps/mobile/lib/features/dashboard/dashboard_page.dart` 的 `_Body` 依次放置结余卡、办公室、场景反馈、`_ClockRow` 和 `_ProgressBar`；倒计时字号是辅助文字，午休只显示提示，已结束或排班异常也没有统一的大字状态。此设计调整首页信息层级、工作状态展示和必要的边界判断，并增加一项本地显示偏好；不改变工资、支出、投资计算口径或小部件字段。首页继续保留设置、下拉刷新、办公室、拍肩、账单、分项、统计说明和底部导航。

## 2. 如何查看原型

打开 [首页交互原型](../prototype/index.html)，点击“先替示例打工人焦虑一下”进入首页。点击“首页显示”可切换“都显示 / 只看下班 / 只看结余”，再次点击收起；浏览器允许本地存储时，刷新原型保留选择。展开“切换演示状态 · 仅原型”，可选择工作中、午休、上班前、下班后、休息日、排班未知，以及完整、A股待更新、核心配置缺失。演示状态控件仅供评审，不进入正式 App。向下滚动可查看原有办公室、账单和明细；资产和桌面分身等入口仍可点击。

## 3. 首页布局与视觉规格

### HOME-DUAL-01 信息顺序

从上到下依次为：现有标题、统计日期及设置；“今日小记”和“首页显示”入口；按用户选择显示的**指标便签卡**（双卡时先时间、后结余）；办公室场景和反馈区；拍肩入口；按配置展示的住房和车贷账单；工资、股票、黄金等分项及统计口径；原有底部导航。正文继续纵向滚动。原有首页设置入口和下拉刷新继续可用。

指标卡优先占据首屏。收起显示设置、使用默认字体与显示密度、320 × 640 dp 可用内容区（扣除系统安全区，包含底部导航）时，双卡模式无需滚动即可完整看到两项**标签和主值**；单卡模式完整显示所选主值。不要求整幅办公室也出现在首屏。展开设置或使用更大字体时允许纵向增长和滚动，不通过裁剪或缩小系统字体来硬塞首屏。

### HOME-DUAL-02 双指标卡

| 部件 | 规格与内容 |
| --- | --- |
| 便签组 | 左右随首页内边距，参考 18 dp；两张卡各自完整成形，使用略有差别的 14–17 dp 圆角、约 1 dp 柔和描边及低对比的 2–3 dp 纸张阴影，取消上一版深色整框与粗分隔线。 |
| 时间卡 | 暖奶油黄 `#F6E8BF`、淡黄褐描边 `#D5C69C`；标题旁用约 17 dp 的手绘钟表图标，正文为状态、约 42 sp 等宽倒计时或同等醒目的状态文字、下班/上班时间与今日计薪进度。双卡时它是第一视觉焦点。 |
| 结余卡 | 纸白 `#FFFDF7`、灰米色描边 `#D7D2C0`；标题旁用同线条的小账单图标，正文为完整性标记、约 42 sp 等宽金额或占位词、状态说明和简短公式。两个主值视觉权重相近。 |
| 衔接细节 | 双卡间留约 6–10 dp 空隙，用两处窄小、低对比的灰绿纸夹/装订环作连接，位置距左右边缘约 26 dp；仅装饰，无文字和交互。取消粗黑横线；单卡时不绘制连接件、空位或多余间距。 |
| 一致性 | 小图标约 1.5–2 dp 线宽，略带手绘感；纸面、阴影、卡片色块和细节沿用现有奶油纸感，与角色、房车、工位的深灰绿轮廓同属一套风格。细卡边是容器，角色及插画仍保持既有粗线条。 |
| 状态色 | 完整金额正值/零为 `#46644E`、负值为 `#AD4736`；部分小计与不可用为深灰中性色，并用文字说明状态；不能仅靠颜色区分。 |
| 自适应 | 390 dp 为参考，320 dp 时按空间合理缩字号或换行；长金额不得溢出、裁掉负号或精度。200% 系统字体下允许卡片增高、文本换行及滚动，保证可读、无重叠；无障碍文本仍包含完整金额。 |

卡片为信息展示，不新增点击行为；可通过卡片上方的“首页显示”设置可见项。现有统计说明继续可达。工作阶段切换、报价更新和拍肩不改变所选指标卡的顺序；场景反馈不能替换完整性提示。

### HOME-DUAL-10 首页显示配置

“今日小记”右侧提供始终可见的“首页显示”入口，至少 44 × 44 dp。点击后在卡片上方展开设置区，标题“首页想看什么？”，使用单选项：

| 选项 | 稳定值 | 首页结果 |
| --- | --- | --- |
| 都显示 | `both` | 时间卡在上、结余卡在下，两卡之间显示装订细节；新安装及旧版本升级默认。 |
| 只看下班 | `time` | 仅时间卡及其计薪进度；结余卡与装订细节不占位。 |
| 只看结余 | `balance` | 仅结余卡；时间卡、计薪进度与装订细节不占位。 |

三个选项互斥且必有一个选中，不提供“两项都隐藏”。选中即刻预览并保存，无需另点保存；面板保持展开便于继续比较，再次点击入口收起。面板说明“只调整首页主卡，不隐藏账单或小部件”。该设置只是界面布局，**不是隐私隐藏**：工资/投资/账单明细、场景、小部件及其他页面仍按既有规则展示；小部件金额隐私继续使用独立开关。设置入口在三种模式下始终可重新找到。

正式版将 `homeMetricsMode` 作为仅本地的展示偏好保存，应用重启、前后台切换、页面切换和重新走引导后保留；旧数据无此值或读取到未知枚举时回退 `both`。读取尚未完成时不先闪现另一种模式；可短暂显示占位。清空账本成功时同时清除这项本地偏好，下一次默认为 `both`。示例模式从 `both` 开始且使用内存中的独立选择，退出后恢复真实模式原有偏好，不写正式账本或偏好。

选择后先立即更新可见卡片，再异步写入本地偏好；连续选择必须按用户最后一次选择的顺序持久化。若最终写入失败，恢复最近一次成功保存的模式，保持设置区可操作并提示“显示设置没存上，请重试”；迟到的旧失败或旧成功不得覆盖更晚的选择。切换布局不改变排班、账本金额、`ledgerRevision`、行情请求或小部件快照，也不重置拍肩和离场状态；隐藏的卡片不参与焦点和辅助功能树。

### HOME-DUAL-03 进度和办公室

进度条属于时间卡，明确标为“今日计薪”，例如 `今日计薪 4.6 / 8.0 小时`，分母与分子均取**统计自然日**的有效计薪时长，沿用 `DayTimeline`；这与本班剩余自然时间是两种口径。午休进度暂停，倒计时继续；下班后在有效当天可显示完成进度。休息日或排班未知时隐藏进度，避免把未知显示成 0%。若分母为 0 则不计算比例；仅看结余时随时间卡一起隐藏。

办公室和反馈区下移，但继续显示。拍肩入口放在场景附近，不再和倒计时挤在一行；人物在场和点击、3.2 秒回应、2.2 秒离场、低动效、可见性及状态切换按 `docs/09` 和现有 `SceneInteractionController` 的约定。时间卡不在拍肩时跳动或被回应覆盖；账单与房车是否配置、深链和辅助功能保持现有约定。

## 4. 下班时间：展示状态与精确规则

### HOME-DUAL-04 状态矩阵

均以账本工资时区为准，默认 `Asia/Shanghai`；下表的 `HH:mm` 为该时区。工作状态优先取同一时刻的 `DashboardSnapshot.workSession`、`phase` 和 `computedAtUtc`。涉及“本班”的结束时刻用完整班次 `activeSession.endUtc`，不要用按自然日切开的 `timeline.shiftEndUtc`。

| 状态及条件 | 时间区标签 | 主值 | 说明/进度 |
| --- | --- | --- | --- |
| 工作中，有有效当前班次 | 距离下班还有 | 距本班结束 `HH:MM:SS` | `预计 18:00 下班 · 按排班计薪`；显示今日计薪进度 |
| 午休或班内非计薪间隔 | 距离下班还有 | 距同一完整班次结束 `HH:MM:SS` | `预计 18:00 下班 · 休息中，工资暂停`；进度暂停，固定支出继续 |
| 上班前，存在可确认的下一班 | 距离上班还有 | 距下一班开始 `HH:MM:SS` | `09:00 上班 · 预计 18:00 下班`；当天进度为 0 或按实际已计薪情况显示 |
| 本统计日已有班次结束且当前不在班 | 本班状态 | 已下班 | `18:00 已下班 · 固定支出继续分摊`；有可确认的下一班时可补充日期时间 |
| 当日无班次且当前不在跨夜班 | 今日排班 | 今日休息 | `今天没有排班，好好休息`；隐藏进度。只有确实能确认下一班时才显示下一班时间 |
| 配置缺失、无效，或阶段所需班次/时刻不可确认 | 排班状态 | 排班待确认 | 给出可进入现有工资/排班设置的说明；隐藏进度，不猜测休息日或显示 `00:00:00` |

上班前选择“距离上班还有”，同时显示预计下班时间，避免把尚未开始的班次误写为正在上班。下班后不继续倒数到负数；不要将上一次班次冒充下一班。无法查到下一班只意味着当前不可展示，不等同于用户之后没有排班。按现有完整班次模型，同一班次中的午休/间隙属于一班，班次终点是该班最后有效计薪区间的终点。

原型的表单明确把中间休息称为午休，因此示例写“午休”。现有 `WorkSessionInfo.unpaidWindows` 只提供时段、不区分午休与其他间隔，正式 App 默认使用“休息中”；仅在数据明确提供午休类型时才写“午休”。没有休息区间时不能提示“午休暂停计薪”。

### HOME-DUAL-05 时钟和边界

1. 根据同一 `nowUtc` 和可确认的目标 UTC 时刻求 `remaining = max(0, targetUtc − nowUtc)`；展示秒数向上取整，再格式化为 `HH:MM:SS`。小时至少两位、不以 24 取模；距离大于 99 小时时不截断。这样最后一秒内不提前显示 `00:00:00`。
2. 到达开始时刻立即转入班内工作/休息状态；到达结束时刻立即转入已下班或相应的新班次状态，结束边界按左闭右开处理。不要因刷新延迟短暂显示休息日、负数或上一个阶段。
3. 含跨夜班时，午夜前后持续指向同一个完整班次终点；预计下班时间在次日时写 `次日 06:00`，在同一统计日时写 `06:00`。更远日期写明确月日，避免“今天/明天”产生歧义。自然日进度和工资仍在午夜切换到当天口径。
4. 前台显示时使用已有时钟驱动按当前时刻重算；可沿用约 250 ms 的现有 tick，但可见秒数每秒更新即可。App 回前台、页面重新可见、系统时间跳变、排班/日期覆盖/工资时区变更时立即重算。后台不为倒计时常驻计时；动画帧和计时器不累加金额。
5. 排班跨版本生效点、跨月、大小周及日期覆盖要使用有效版本与真实班次；数据不足时显示待确认。不得仅按星期、设备本地时区或 `now.hour` 推测工作状态。

参考样例（均为工资时区）：

| 输入 | 预期 |
| --- | --- |
| 09:00–12:00、13:00–18:00，14:36:00 | `距离下班还有 03:24:00`，预计 18:00 下班 |
| 同班 12:30:00 | `距离下班还有 05:30:00`；午休中，工资不增长，固定支出继续 |
| 同班 08:45:00 | `距离上班还有 00:15:00`；09:00 上班，预计 18:00 下班 |
| 同班 17:59:59.900、18:00:00 | 前者显示 `00:00:01`；后者显示 `已下班` |
| 11 月 30 日 22:00 至 12 月 1 日 06:00，23:59:59 | `06:00:01`，提示次日 06:00；零点后 `06:00:00`，班次与人物不提前结束 |

## 5. 今日生存结余：展示与完整性

### HOME-DUAL-06 数值口径

继续使用领域层提供的 `DashboardSnapshot.total` 和完整性，按现有契约先以完整精度求和，再四舍五入到分：

```text
今日生存结余 = 今日工资估算 + 各类投资今日浮动 − 今日已分摊住房与车贷
```

当前已实现资产按 A股、黄金契约处理；若 M7-FUND 已合入，则基金今日浮动及部分基金已知小计按其专属契约加入，不能由首页另算或把基金塞进股票字段。住房为房贷、房租、暂无三选一，车贷独立。本金、利息拆分未知不等于月供未知。公式描述应保持概括，不把基金能力表述为本次已经实现。

金额示例：完整负值 `−¥55.26`；完整正值 `¥194.74`；真实零 `¥0.00`；统一消除 `−0.00`。大额必须完整呈现，可换行；主卡和辅助功能都不能把未知当 0。

### HOME-DUAL-07 完整性与来源

| 领域结果 | 主值和标记 | 说明 |
| --- | --- | --- |
| `complete` | 完整金额；依据正负展示“暂时领先”或“努力回本” | 可以展示完整结余对应的语气；按现有来源策略显示报价时间和质量。 |
| `partial` | 已知小计，中性色，标“部分小计” | 紧邻主值说明缺少的项目，例如“A股今日浮动待更新，当前仅显示已知小计”；多个未知项目可换行，不依据小计推断最终盈亏。 |
| `unavailable` | `待配置`，标“不可计算” | 明确核心配置不可用及可修复位置；不显示虚假的 0 或旧完整数字。 |
| 缓存仍有效、但报价 `stale` | 可以参与现有契约允许的结果；标“缓存/陈旧” | 显示真实的报价时间；不能把 `computedAt` 当作 `quotesAsOf`，不能标为实时。跨交易日基准失效则遵照契约变为未知。 |

`partial` 和 `stale` 不是互斥关系，二者同时存在时都要能看到。展示具体缺项时需覆盖住房、车贷、股票、黄金及已接入的基金，而不是固定写“投资待更新”。本金拆分缺失仅提示拆分不完整；已知 0 持仓、住房为暂无、无车贷均是已知 0。滚动到明细时可追溯各项及统计说明；单项缺失不抹掉其他已知分项。

## 6. 交互、可访问性与隐私

### HOME-DUAL-08 刷新和返回

首页下拉刷新沿用现有行情刷新；等待期间本地工资、计时及支出继续按时钟计算。请求失败保留可用缓存及真实时间，首次无缓存保持未知。切换底部标签、进入设置后返回及恢复前台时，可见指标重新对齐同一快照和时钟。状态切换、页面滚动、拍肩均不写账本、不请求额外行情、不单独发布小部件；显示设置仅写入独立本地界面偏好。

### HOME-DUAL-09 辅助功能

屏幕阅读器按“页面标题 → 首页显示入口 → 已选择显示的时间和/或结余 → 场景/后续内容”的顺序读取；隐藏卡片及装订装饰不被朗读。显示设置提供单选组名称、三个选项和当前选中状态，展开/收起状态可读；200% 字体下选项允许换行或改为纵排。时间示例语义：`距离下班还有 3 小时 24 分钟，预计 18 点下班`；金额需包含正负、单位与“部分小计/不可计算”。倒计时和金额每次刷新不触发自动播报；用户主动聚焦时读取当前值。进度提供可理解的计薪百分比或时长，休息/未知时不提供虚假进度。设置、单选项、拍肩、账单和底部导航的有效触控区域至少 44 × 44 dp；文字和状态保持足够对比，不能只依赖颜色。

现有个人账本仍保存在本地，行情请求仅发送标的 ID。首页重排不新增数据采集、日志或网络参数；小部件隐私开关、隐藏金额和快照语义不变。

## 7. 实施建议与已发现的边界

- 先审阅 `dashboard_page.dart` 中 `_Body`、`_ClockRow`、`_ProgressBar`、`_CompletenessNote`、`_FeedbackArea`、`_Entries` 和现有测试；可提取独立时间/结余展示组件，但不得复制金融计算。
- 使用 `finance_core` 的 `WorkSessionContext`、`WorkSessionInfo` 和 `DashboardSnapshot`，将倒计时展示的纯映射集中在可测试函数或展示模型中。状态和金额应来自相同时间点，避免 UI 各自读不同的时钟。
- 当前 `ScheduleExpander.workSessionContext` 中 `session.endUtc.isBefore(now)` 对**恰好等于结束时刻**不认作已结束；现有 `_ClockRow` 对无效排班可落入休息提示。实施时先补边界测试并修正，让完整班次、倒计时、场景离场一致，不能只在 UI 假造另一套状态。
- 将 `homeMetricsMode` 作为独立的 UI 偏好保存，例如数据库中单独的偏好表或等价的本地持久存储；选定实现须支持原子单值写入、升级默认值和清空。不要直接复用当前会提升 `ledgerRevision` 并发布小部件的 `LedgerRepository.updateSettings`/`_commitSettings`。如果使用 SQLite，按实施时已有的最新 schema 增量迁移，并同时更新新建库及旧库升级；不得覆盖并行 M7-FUND 的迁移。
- 不改变工资自然日区间、月分母、金额精度、排班覆盖或 `DashboardSnapshot` 既有财务口径；如为正确解析跨版本班次必须修改共享查询，覆盖 `docs/09` 的跨夜、离场与既有领域测试。
- 当前基金设计及其可能的并行改动由 M7-FUND 管理。开发前核对实际分支和工作区，保留已有改动；若基金已存在，用其公开的缺项与小计，不修改它的语义。小部件桥接若无修改，不需要更改 schema 或原生代码。
