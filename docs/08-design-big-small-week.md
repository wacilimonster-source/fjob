# 大小周排班 · 产品设计草案

版本 0.1（待确认）· 2026-11-05 · 未实现，仅设计评审

## 1. 目标

在现有“固定周排班”之外增加“大小周”：

- 大周 6 个工作日、小周 5 个工作日，按自然周交替。
- 工资分母、今日工资、月累计、跨夜班、日期覆盖和版本分段全部按真实排班计算。
- 引导可完成录入，设置可修改，历史版本可解释。
- 同时按最新要求收敛发布范围：仅 Android，仅产出 APK。

## 2. 规则定义（建议默认值）

| 项 | 建议规则 |
| --- | --- |
| 周起始 | 周一至周日，按工资时区（默认 Asia/Shanghai） |
| 小周 | 周一至周五工作（5 天） |
| 大周 | 小周基础上增加 1 个额外工作日（6 天） |
| 额外工作日 | 默认周六，可切换为周日 |
| 锚点 | 指定某一自然周（以周一表示）为大周，之后每两周循环 |
| 锚点默认 | 引导当周为大周，用户可改为“本周小周” |
| 班次 | 大小周共用同一上下班时间与午休；额外工作日沿用同一班次 |
| 日期覆盖 | 具体日期的覆盖优先于大小周模板，空区间表示休息/请假 |
| 版本 | 大小周配置随薪资/排班版本保存；切换按生效日期分段 |
| 计算 | 月分母 = 当月所有真实计薪秒数；整月版本不变时累计仍等于月薪 |

## 3. 用户流程

### 3.1 引导第 2 步（O03）

在现有“你几点上线，又几点归还自己？”中加入排班方式：

```text
排班方式      [ 固定星期 ]   [● 大小周 ]

小周          周一 周二 周三 周四 周五
大周          周一 周二 周三 周四 周五 [周六]
额外工作日    [● 周六]  [ 周日 ]
本周          [● 大周]  [ 小周 ]

未来四周
  11/02–11/08   大周 · 6 天
  11/09–11/15   小周 · 5 天
  11/16–11/22   大周 · 6 天
  11/23–11/29   小周 · 5 天

本月计薪      23 天 · 184.0 小时
```

- 固定星期模式保留现有 7 天选择与自定义班次。
- 大小周模式核心工作日固定周一至周五（首版不做自定义核心日）。
- 切换“额外工作日”或“本周大/小周”后，未来四周预览与本月计薪天数/小时即时重算。
- 若月薪 > 0 且小周没有任何计薪时段，阻止继续，提示“小周没有计薪时段，先给工资安排一个出场时间”。
- 若额外工作日与核心工作日重复（例如核心已含周六），阻止并说明冲突。

### 3.2 核对页（O06）

排班摘要示例：

```text
本月排班   大小周 · 本周大周 · 额外周六
           23 天 · 184.0 小时
```

固定星期模式沿用现有“21 天 · 168.0 小时”。

### 3.3 设置与编辑

- 设置中的收入/排班编辑增加同样的“固定星期 / 大小周”控件。
- 修改默认从本月首日生效；也可选“从今天生效”。
- 若生效日不在周一，界面提示：“本周会按两套排班分段计算，首页会标注按分段配置估算。”
- 历史月份保持原配置与分母，不因新版本改变。

### 3.4 首页

- 工资条目备注追加“大小周”：
  `到手月薪 ¥12,000 · 本月排班 184.0 小时 · 大小周`
- 若为本月内切换版本：`按分段配置估算 · 大小周`
- 排班进度、倒计时、午休、休息日逻辑不变。

### 3.5 资产、固定支出、小部件

- 不新增配置；工资与总览自动使用大小周结果。
- 小部件快照的 `wage`、`total` 由同一引擎生成，不增加字段。

## 4. 计算规则

### 4.1 周类型

```text
mondayOf(date) = 该日期所在自然周的周一（工资时区）
weeks = (mondayOf(date) - anchorMonday).inDays / 7
weekType = weeks 为偶数 ? 大周 : 小周
```

- 以日期而不是 ISO 周序号判断，跨月、跨年稳定。
- 同一自然周在两个月保持同一类型。
- 锚点必须归一化到周一。

### 4.2 当日模板

```text
intervals(date) = override(date) ?? (大周 ? bigWeek : smallWeek)
```

- 覆盖整天，替换当日大小周结果；不会只改半天。
- 跨夜班仍按自然日与月份切开；大小周只决定班次是否存在。

### 4.3 月分母与今日工资

- 月分母 `D(v,m)`：该版本模板展开当月所有自然日，扣除午休，跨夜班按自然日/月切开后的总秒数。
- 今日工资、月累计、版本分段沿用 CALC-WAGE：每个版本使用自己的大小周配置与整月分母。
- 版本月内不变时，整月累计等于月薪（守恒）。
- 月中切换版本时，每段仍使用所属版本的整月分母，界面标注“按分段配置估算”。

### 4.4 日期覆盖

| 场景 | 结果 |
| --- | --- |
| 大周周六设为休息 | 当天无计薪，月分母减少 8 小时 |
| 小周周六设为上班 | 当天按覆盖区间计薪，月分母增加 |
| 请假/调休/半天 | 用覆盖区间表达，优先于大小周 |
| 法定节假日导入 | 后续用带版本的覆盖记录表达，不改变大小周算法 |

## 5. 数据模型

### 5.1 领域

```dart
final class WeekAlternation {
  final WeekTemplate smallWeek;   // 周一至周五
  final WeekTemplate bigWeek;     // 小周 + 额外工作日
  final LocalDate anchorMonday;   // 该周为大周
}

final class ScheduleVersion {
  final WeekTemplate week;              // 固定周模式
  final WeekAlternation? alternation;   // 大小周模式
  WeekTemplate templateFor(LocalDate date);
}
```

- 固定周版本 `alternation = null`，行为完全不变。
- 大小周版本 `week` 仍保存小周模板，兼容旧读取路径。
- 校验：锚点必须是周一；小周/大周至少一个班次；大周不得少于小周；额外工作日不得与核心工作日重复。

### 5.2 数据库

- `schedule_versions` 新增 `alternation_json TEXT NULL`（schema v3）。
- 旧 v1/v2 数据 `alternation_json` 为空，按固定周读取。
- 迁移只加列，不重写历史版本。

### 5.3 引导草稿

新增字段：

```text
scheduleMode: fixed | bigSmall
extraWeekday: saturday | sunday
anchorIsBig: true | false
```

仍保留 `workdays[7]` 作为小周/固定周的工作日；大小周下 `workdays` 固定为周一至周五，由额外工作日派生大周。

## 6. 边界与异常

| 情况 | 处理 |
| --- | --- |
| 月薪 0 + 大小周无任何班次 | 允许，工资为 0 |
| 月薪 > 0 + 小周无班次 | 阻止确认，字段旁说明 |
| 月薪 > 0 + 大周无班次 | 阻止确认（大周必须有小周之外的有效班次） |
| 额外工作日与核心工作日重复 | 阻止，提示冲突 |
| 月初/月末跨周 | 按自然周类型计算，不按月份重新起算 |
| 2 月 28/29 天 | 使用真实天数与真实周类型 |
| 有大周周六的月份 | 可能 23 或 24 个计薪日（取决于该月周六数量与锚点） |
| 覆盖日期落在大小周班次上 | 覆盖优先，月分母即时重算 |
| 月中切换固定周/大小周 | 新版本按生效时刻；显示分段提示 |
| 切换锚点类型 | 新版本生效，历史月份不变 |
| 系统时区变化 | 统计时区保持 Asia/Shanghai，周类型按统计时区 |

## 8. 待确认问题

1. 小周是否固定周一至周五？是否需要允许自定义核心工作日（如周一至周四）？
   - 建议首版固定周一至周五，减少组合与测试面。
2. 额外工作日是否只允许周六/周日二选一？是否需要同时支持“周六+周日”或轮换？
   - 建议首版单选，默认周六。
3. 引导默认“当周为大周”是否合适？是否必须让用户显式选择本周类型？
   - 建议默认当周大周，但控件可见、可切换。
4. 额外工作日的班次/午休是否与工作日一致？
   - 建议沿用；需要不同工时时用日期覆盖，后续再提供“周末班次”独立配置。
5. 切换生效日默认本月首日；若用户选择“今天”且不在周一，是否接受本周分段？
   - 建议接受，但显示明确提示。
6. Android-only / APK-only 的收敛范围：
   - 删除 `apps/mobile/ios/` 与 iOS 工作流；
   - 发布只保留 APK，不再构建/上传 AAB；
   - 历史 Release 里的 AAB 保留不动，新版本不再产出；
   - 文档、CI、`toolchain.lock.json` 同步改为 Android-only。
   请确认是否按此执行。
